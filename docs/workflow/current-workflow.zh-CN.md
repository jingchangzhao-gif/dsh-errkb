本文是下一次施工时的唯一恢复入口，只保存尚未解决的工作。某个问题通过验收后，应从中英文活动表中直接删除；历史证据放入实施计划、CHANGELOG、测试记录或验收文档，不在这里不断累积“已完成”列表。

## 工作规则

每个问题都按以下顺序处理：

```text
读取当前状态
  → 复现问题
  → 确认唯一责任层
  → 完成最小而完整的修改
  → 运行针对性测试
  → 运行公共质量门槛
  → 同步中英文文档
  → 从本文删除已经解决的问题
```

同一时间只能有一个问题处于 `IN PROGRESS`。前置问题未完成时，不开始依赖它的任务。源码中存在实现并不代表功能完成；它还必须能通过预定用户入口实际调用。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| `NEXT` | 下一项应当施工的工作 |
| `IN PROGRESS` | 当前唯一正在修改和验证的问题 |
| `OPEN` | 已确认存在，等待前置条件 |
| `BLOCKED` | 当前环境无法完成，并明确写出缺少的外部条件 |

本文刻意没有 `DONE` 状态；解决的问题会从活动表删除。

## 单项更新格式

开始施工时：

1. 在中英文文件中只把一行改为 `IN PROGRESS`。
2. 在该行记录复现命令或文件证据。
3. 只修改责任层及其测试和文档。

关闭问题时：

1. 运行该行的完成条件。
2. 运行下方公共门槛。
3. 把长期证据写入对应实施计划任务、CHANGELOG 或验收文件。
4. 从中英文活动表删除该行。
5. 把下一条已经满足依赖的问题改为 `NEXT`。

## 公共质量门槛

开发时运行相关子集，发布前运行完整集合：

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm format:check
go vet ./...
go test ./...
cue vet ./spec/...
```

数据库验收还需要 `ERRKB_TEST_DATABASE_URL`；打包任务还需要发布脚本检查和干净 VM 验收。
